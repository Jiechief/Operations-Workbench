# 运营工作台 Operations Workbench

以 **国际站商家优爆品数据表**（`截至10.24数据(1).xlsx`，200 家 × 98 列）为核心的单文件运营工作台。
数据逐格原样内置，页面只做展示与计算，**不改动任何原始数值**；待办、跟进笔记、AI 配置写在浏览器 localStorage，无后端。

骨架沿用 [customer-workbench](https://github.com/Jiechief/customer-workbench)：一个 HTML 主程序 + 本地代理脚本 + 双击启动脚本。

## 数据保真

- 由 `openpyxl` 从原表逐格导出到 `ops-data.js`，数值不做任何四舍五入，空值保持 `null`
- `meta.nonnull`（98 列各自非空数）与 `meta.numSum`（数值列合计）随数据一起内置
- 页面「校验数值合计」会按当前渲染所用的数据重算并比对，结果为 **数值列合计 98 / 98 全部一致、非空数 98 / 98 全部一致**
- 比例、金额、日期只在显示层换算（如 `0.6666666666666666 → 66.7%`、`20230703 → 2023-07-03`），原值在详情面板与 CSV 导出里保持原样
- 字段分组：基础 3 / 行业 4 / 服务 3 / 优爆品 10 / 商品结构 13 / P4P推广 18 / 组织归属 15 / 不满足原因 15 / 历史对比 4 / 行业基准 13 = 98 列

## 排序规则

1. 数值列按数值比较，文本列按中文拼音 `zh-Hans-CN` 比较
2. **空值永远排在末尾**，与升 / 降序无关（`—` 才是空，`0` 是真实值）
3. `服务时长分类` 用自然序：首年 → 次年 → 第3年 → 第4年 → 第5年 → 第6年及以上
4. `是否金品` 按 Y 优先
5. 同值时按公司名、再按原表行号，保证排序稳定可复现
6. 「还原原表顺序」按钮回到 Excel 的原始行序
7. 派生列（当季完成率、当季缺口、全年完成率、投广缺口）按计算值排序，公式为：
   - 当季完成率 = 当前优爆品数 ÷ 当季度参考目标（无目标 → 空 → 排末尾）
   - 当季缺口 = `max(0, 当季度参考目标 − 当前优爆品数)`
   - 投广缺口 = `max(0, 推荐投广品数 − 推广品数)`

## 换数据的两条路

后台随时能导出新表，所以工作台按「**换数据不能静默出错**」设计。两种方式都支持，推荐长期用 A、临时用 B。

### A. 脚本重生成内置数据（推荐，历史进 git）

把后台导出的 xlsx 拖到 `更新数据.bat` 上（或双击后粘贴路径），它调用 `tools/导出工作台数据.py` 重写 `ops-data.js`；再双击 `更新到云端.bat` 提交。

- 自动定位表头行（后台导出前面多几行标题也能识别）
- 逐格原值，日期转 `YYYYMMDD`，空值 `null`，不做任何四舍五入
- 自动剔除汇总行（公司名含 合计/总计/小计/汇总/平均 或纯数字）、按 `admin_mbr_id` 去重
- 同时写入 `meta.nonnull` / `meta.numSum` 作为校验基准，页面自检直接引用
- 已验证：用同一份 `截至10.24数据(1).xlsx` 重跑，生成的行数据、列类型、分组、非空数、逐列合计与原内置文件**逐字段一致**

### B. 页面内导入（快，存在本机浏览器）

「数据源与设置 → 导入新表格」选 xlsx/csv，流程是**预览 → 确认 → 落地**：

1. 解析后先看**导入预览**：工作表与表头行、行列数、同名匹配列数、关键列覆盖率（公司名称 / 当前优爆品数 / 当季度参考目标）、体积估算、首行样例
2. 有异常会列在「需要你确认」里：缺关键字段、原表有而新表没有的列、新增列、汇总行剔除数、主键重复、表头行位置、体积接近 localStorage 上限
3. 点「确认导入」才会替换数据；替换前自动把当前数据写入 `df_ops_workbench_prev_dataset_v1`，可用**「撤销上次导入」**退回上一层；**「恢复内置数据」**退回随仓库发布的版本

### 换数据后的自动反应

- **时效横幅**：主区顶部常驻「数据截至 X（N 天前）· 来源 · 行数×列数 · 快照 N 份 · 自检 n/n」，超过 45 天提示「数据偏旧，建议从后台重新导出」
- **导入自检清单**（数据源与设置页，11 项）：行数>0、列宽=98、主键列存在、主键唯一且非空、无汇总行残留、逐列合计与基准一致、关键列覆盖率、目标列覆盖率≥70%、列名与原表匹配≥90%、派生公式抽查、数据新鲜度≤45 天
- **历史快照与环比**：每次确认导入会把上一份的汇总（家数、优爆品合计、达标家数、缺口、今日下降、零优爆品 + 每家优爆品数）留成快照，最多 12 条；总览看板出现「与上一份数据的对比」，直接显示这次换数据的净变化；快照只存汇总不占空间，可在快照表里删除
- 待办任务与商家跟进记录按 `admin_mbr_id` 存本地，**换数据不会丢**

### 已知边界

- 页面导入的数据只存本机浏览器（`df_ops_workbench_dataset_v1`），换设备/清缓存会没；要留档请用方式 A
- 总表当前一次性渲染，200 行很稳；若后台导出涨到几千行，需要补分页/虚拟滚动（已预留，`currentList()` 单点改造）
- P4P 三列只有部分商家有值（本表 100/200），按空值处理且排末尾，聚合时不计入——覆盖率会在自检清单和 KPI 卡的「有数据 N 家」里说明

> 注：原表 P4P 三列（本月 / 上月消耗、环比增额）只有 100 家有值，优化师相关列只有 10 家有值，页面按空值处理并排在末尾，不参与合计。

## 本地使用

- **方式一（推荐）**：双击 `启动本地服务器.bat` → 自动打开 `http://localhost:8000`
  `server.py` 除静态文件外还提供同源 `POST /proxy?<外部地址>` 转发，浏览器跨域被拦时页面自动改走代理
- **方式二**：双击 `直接打开工作台.bat`，用 `--disable-web-security` 独立实例打开 `file://` 页面（无需服务器，但该实例不要用来逛别的网站）
- **方式三**：双击 `更新到云端.bat` 一键提交并推送
- GitHub Pages 需在 **Settings → Pages** 选 `Deploy from a branch / main /(root)`，之后可用 `https://<用户名>.github.io/Operations-Workbench/`

## 文件结构

```
运营工作台.html      主程序（界面 + 逻辑）
ops-data.js          内置数据（原表逐格原值 + 列元数据 + 校验用合计）
xlsx.bundle.js       SheetJS 1.15.0（Apache-2.0），供页面内导入新表格
index.html           入口跳转页
server.py            本地静态服务器 + /proxy 外部接口转发
tools/导出工作台数据.py  Excel → ops-data.js（表头定位 / 脏行剔除 / 校验基准）
更新数据.bat          拖 xlsx 进来即可重生成内置数据
启动本地服务器.bat     起服务并打开页面
直接打开工作台.bat     免服务器直开（独立浏览器实例）
更新到云端.bat        一键提交推送
```

## 本地数据

- 键前缀 `df_ops_workbench_`（settings / tasks / notes / ai_providers / ai_usage / ai_chat / dataset），与客户跟进工作台（`df_customer_workbench_`）互不干扰
- API Key 只存本机浏览器，导出的备份 JSON 不含 Key
- 部分浏览器在 `file://` 下禁用 localStorage，页面会自动降级为内存存储并提示
